# 后台巩固与审计

## 后台会做什么

- 从 DSH 目标/任务书/子代理报告/后台任务结果抽取候选记忆和状态机；
- 向量近邻 + 属性重叠去重，旧条目归档并保留 `merged_from` 链接；
- 检测矛盾事实，写双向 `possible_conflict`；手工取消后写入抑制表，不再自动标记；
- 多会话重复/用户确认/可验证检查通过后，线索转事实；
- 共同召回统计建议 `co_recalled` 链接与思维链；
- 按新近度/访问/采用率/置信度/分类计算显著度，低显著度归档；
- 归并同义属性名并重建视图。

## 什么时候看审计

- 用户问“为什么这条被合并/归档/改了”；
- 需要撤销某次后台写；
- 需要确认任务是否真的在跑。

## 工具

- `omb_admin action=audit [limit]`：列最近审计；
- `omb_admin action=rollback auditId=N`：按 inverse 回滚一次；回滚本身也记审计；
- `omb_status`：数据库、实体计数、嵌入、队列开关的实测读数。

## 回滚边界

- 支持：写入归档、归档/取消归档、链接/取消链接、patch 恢复旧属性；
- 一次只回滚一条审计；复杂合并按审计记录逐条处理；
- 回滚不是“时间旅行”：后续写入不会被自动撤销；不要声称回滚了整个会话。
