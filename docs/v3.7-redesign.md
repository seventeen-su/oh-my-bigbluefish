# OMB v3.7 重构方案（思维链质量 / 记忆库 / 上下文优化）

> 输入：四份研究报告（`docs/research/2026-10-18-{memory,reasoning,context,dsh-capabilities}.md`）
> + 本机实测语料（391 个会话 / 256,316 事件 / 49,442 次工具调用 / 283.7MB 压缩日志）。
> 本文件只写**已裁决的施工内容**；未裁决项集中在 §6，等用户拍板。

## 0. 一句话结论

三个组件的问题不是"功能少"，而是**投入与生效错位**：

| 组件 | 现状 | 证据 |
| --- | --- | --- |
| 记忆库 | 数据结构与迁移做得比同类开源实现严谨，但**写错（回顾体进用户库）、查不准（中文 bigram OR + 无分数下限）、报得贵（单次召回 3,877 字符）** | memory §1.8/§2；DB 71 行、143 次写→83 准入 |
| 思维链 | 默认工作点 `standard` 注入 **0 字符**；`omb_focus` 只改文字、不改真实 `reasoningEffort`；`omb_verify` 是循环依赖，391 会话仅 56 次 | reasoning §0/§1.2/§1.3 |
| 上下文 | `admission.ts` 与 `context:pressure` 服务**零生产消费者**；健康行结构性未测量；68/68 份 status 自相矛盾；对全部 prompt token 的贡献 **0.00035%** | context §1.2–§1.7 |

## 1. 设计原则（本轮不变）

1. **宿主优先**：会话读取/搜索、压力投影、压缩、工具结果裁剪归 DSH；OMB 不重复实现（dsh-capabilities §4.1）。
2. **拉取优先 + 前缀稳定**：常驻预算 120 字符（现用 71）；任何逐回合变化的注入必须有明确收益并限幅（context-budget.md）。
3. **热路径零 LLM**：不引入写入时抽取、查询改写、答案复审；独立复核只在显式要求时用 subagent。
4. **读数必须真**：不承诺未接线行为；状态面给时间、总量、窗口与采样来源（reasoning §4.1）。
5. **中文检索留在 OMB**：DSH `fts5(unicode61)` 实测不能做中文子串召回（memory §4.1），且其搜索索引在本语料冷建 >30s（dsh-capabilities §2.3）。

## 5. 门禁与回滚

- 门禁：`npx tsc --noEmit` / `npx eslint .` / `npx vitest run` / `node scripts/build.mjs`；只有全绿才提交。
- 回滚：每个机制一个 config 开关（`memory.residentHint`、`recall.defaultDetail`、`reasoning.effortMapping`、`context.ledgerOnly`），代码保留 legacy 分支一个版本。
- 提交：Lead 独占；构建产物最后生成一次；C 盘副本按既有流程 `git pull` + 产物同步 + relink + 重启验证。

## 6. 本轮明确不做

- 不改模型内部（无 PRM/解码干预/budget forcing）；不加写入时 LLM 抽取；不做社区摘要/GraphRAG/三级记忆。
- 不替换宿主压缩、不自造 pruner、不把会话历史搬进 OMB。
- 不在常驻预算外新增第二个常驻提示；不新增第 11 个工具（新能力优先做参数）。
- 不根据"20 轮零拉取"删工具（全库 216 次/39,081 step，判据会误杀全部视图）。
