# OMB v4.9.7 — 用户断言：模糊去重与压缩后追忆修复

> 用户实测缺陷（x3）：**压缩之后追忆压缩前的内容总被拒绝**；以及用户断言命中
> 既有条目时，因为走的是全量内容哈希比对，命中不了近似内容，同一条在库里越积越多。

## 1. 根因

两条独立问题叠在一起：

1. **准入侧**：`isGroundedInUserMessage` 只核对**当前**最后一条用户消息。宿主压缩后，
   原话已被摘要替换，同一条此前已确认过的内容再写一次会在准入阶段以
   `user-claim-unverified` 被拒——不是因为它错，而是因为"现在看不到原话"。
2. **去重侧**：`findSameContent` 只比 `contentHash`（逐字全文哈希）。压缩后模型追忆
   时常重排空白、换标点、改一两个字，哈希对不上 → 漏判重复；而用户断言命中一个
   **候选**时，又被当作"重复"退回，永远升不了级。

## 2. 修法

### 2.1 模糊同内容判据

- `normalizeForCompare`：NFKC + 去空白/中英文标点 + 小写；
- 新增 `textSimilarity`（字符 bigram Dice）与 `FUZZY_DUPLICATE_MIN = 0.9`；
- `findSimilarContent`：先按内容哈希判 `exact`；否则按归一化 bigram ≥ 0.9 判 `fuzzy`；
- **数字保护**：归一化后数字串不同（`case-0` / `case-1`、端口 8080/8081）一律不算近似，
  避免把"参数不同"的两次执行合并；
- 只认活跃、同 scope 条目；查询失败返回 `undefined`（去重是优化，不是安全边界）。

### 2.2 用户断言命中既有条目 → 就地升级

- 本次 `assertedBy=user`、库里命中条目还是候选/事件时：把既有条目 `assertedBy` 改为
  `user`，**正文、id、来源、observedAt 一字不改**，回执写"已升级"与匹配方式（逐字/近似）；
- 已确认的同内容再写：回执写"无需重写"，而不是把它当重复退回。

### 2.3 压缩后的准入兜底

- 准入仍是严格判据：**当前用户消息里核对不到原话、且没有任何既有已确认记录 → 继续拒绝**
  （防伪造不放松）；
- 仅当库里已有同内容/近似内容且 `assertedBy=user` 时，承认"此前已核对通过"这一事实，
  记为 `verification='previously-verified'`，回执注明"当前上下文没有原话（常见于压缩之后）"。

## 3. 明确边界

- 0.9 是保守阈值：只收标点/空白/个别字差异；更大幅度的改写仍视为新条目
  （逐字保真优先，不静默合并两份不同原文）；
- 数字不同不合并（端口、版本、序号、测试名是事实）；
- 首次追忆、库里没有已确认记录的内容仍然会被拒绝——这不是"压缩豁免"；
- 模糊匹配只影响去重/升级判定，不改变 `contentHash`（逐字保真证据仍是原文哈希）。
