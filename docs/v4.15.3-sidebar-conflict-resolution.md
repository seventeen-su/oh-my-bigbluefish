# OMB v4.15.3 — 侧边栏手动冲突裁决

> 4.15.0 同功能收尾（x3）：指令第 3 项里的"手动冲突解决"落地。
> 详情页的"可能相关/冲突"列表从"只展示"变成**可手动建关联/标取代**。

## 1. 两个动作

| 动作 | 语义 | 写入 |
| --- | --- | --- |
| `relate` | 建 `related` 边（普通关联，无时序含义） | `upsertEdge(fromId→toId, type:'related')` |
| `supersede` | `fromId`（新）取代 `toId`（旧） | 旧条目 `validTo=max(now, observedAt)` + `supersededBy=fromId`；`supersedes` 边从新指向旧 |

`supersede` 与 `omb_remember(supersedes=…)` **同一语义**：非破坏——旧条目仍在库里，
历史可查；它只是不再作为有效结论注入召回。UI 没有新建记忆/改正文/删除入口。

## 2. 判据（全部确定性、失败如实拒绝）

- 两条 id 必须存在、不能相同、**必须同作用域且同一个库**（跨库不裁决）；
- 必须都**活跃**（`validTo`/`supersededBy` 均为空）；
- `supersede` 写入后**查回验证**（`supersededBy` 必须等于新条目 id）；
  supersedes 边失败时回执如实说"状态已生效、只是 omb_relate 追不到这一跳"；
- 时钟未接线时写动作拒绝（不伪造时间）；动作进活动日志（`write`，不含正文）。

## 3. 路由与页面

- `POST /omb/api/resolve` `{ action: "relate"|"supersede", fromId, toId }`：
  成功 200 / 业务拒绝 409 / 参数错 400；沿用同源检查、JSON-only、no-store；
- 详情页"可能相关/冲突"每条给两个按钮：「建立关联」「本条取代该条」；
  动作后刷新详情/列表/概览并原样显示服务端回执。

## 4. 边界

- 裁决**不会**自动创建新记忆、不合并正文、不硬删除；
- 不提供"跨项目/跨作用域"的冲突处理（那是数据边界，不是 UI 便利问题）；
- 没有模型工具入口：仍是用户点击（路由只在本机回环监听）。
