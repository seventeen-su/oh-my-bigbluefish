# OMB v4.15.1 — 侧边栏手动确认动作

> 4.15.0 同功能收尾（x3）：把"只读可见"补成"可在页面上手动确认/撤销确认"。
> 版本口径：新界面只升 x2；同一界面的能力收尾升 x3。

## 1. 做法：一个操作，两个调用方

写逻辑**没有复制**：`confirm.ts` 新增 `createConfirmAction(confirmDeps)`，
内部复用 `/omb-confirm` 的 `runPromote` / `runUndo`（查库、候选形态校验、写回、
查回验证、审计、相关条目、观测口全部同一份）。

- `/omb-confirm <id>` 命令：用户输入命令行；
- 侧边栏按钮：`POST /omb/api/confirm` `{ id, action: "confirm" | "undo" }`；
- 两者命中同一条服务方法，回执文本也同一套；UI 没有独立写路径。

## 2. 路由与安全

- 新增 `POST /omb/api/confirm`：仅接受 `application/json`（否则 415）、
  `{id, action}` 必填（否则 400）、成功 200 / 业务拒绝 409（带回执文本）；
- 同源检查沿用 v4.15.0（Origin 与 Host 不一致 403）；响应 `no-store`；
- **没有模型工具调用它**：模型无法发起这个 POST；权限仍是"用户点击"，
  路由只在本机回环监听上存在；
- 审计 `sessionId` 为 `null`：UI 是全局面板，不绑定某个会话；
  撤销仍要求审计最后一次动作是 confirm（没有审计证明照样拒绝）。

## 3. 页面

详情面板按记录状态显示按钮：

- 候选（`semantic`/`procedural` + `assertedBy=model` 且活跃）→「确认为已确认」；
- 已确认且审计最后动作是 confirm →「撤销确认」；
- 其余记录显示"当前没有可执行的确认动作"；
- 动作后刷新详情、列表与概览，并显示服务端回执（失败原因原样展示）。

## 4. 边界

- **不提供**：新建记忆、编辑正文、自动 supersede、删除（这些仍走模型工具/用户命令，
  或留给后续明确设计）；相关条目仍是提示，不是自动裁决；
- UI 动作只改 `assertedBy`（确认/撤销），不刷新时间、不改正文与来源；
- 无 `confirm` 依赖（`config.confirmCommand=false`）时 `act` 如实拒绝，不假装成功。
