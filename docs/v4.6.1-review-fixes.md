## P1：项目证据的成功/失败语义

### 问题
`dsh/session.ts` 的 `ok` 来自工具结果 `isError/error`；shell 工具对非零退出码通常仍返回
`isError:false`，只在渲染文本末尾附 `[exit code: N]`。因此旧实现可能把失败的
`pnpm test` 显示为通过（假绿灯）。

### 修法
- `dsh/project-evidence.ts` 新增 `parseCommandOutcome(text)`：
  - `\n[exit code: 0]` → `succeeded`；
  - `\n[exit code: N≠0]` → `failed` + `exitCode`；
  - `\n[exit code: null]` / `\n[killed by signal: X]` → `unknown`/`failed`；
  - **没有标记 → `unknown`**，不再当成成功。
- 证据结构改成 `commandOutcome: 'succeeded'|'failed'|'unknown'` + `exitCode`；
  `unknown` 在 `omb_project` 显示 `⚠️未知`，不显示 ✅。
- 只记录 shell 类工具；工具级 `isError` 不再参与证据结论。
- 旧版 v1 落盘文件的 `ok` 字段**一律降级为 unknown**（历史绿点不可信）。
- 测试覆盖：退出码 0 / 非零 / null / 无标记 / 信号终止；无标记不得显示通过。

### 仍未做
没有直接读取 shell 执行器的结构化 `ShellRunResult.exitCode`（当前从渲染文本解析）；
DSH 若未来在工具结果 `meta` 暴露 exitCode，应改为读结构化字段。

## P1：临时任务约束不得变长期记忆

### 问题
旧 `classifyUserMessage` 只按关键词（以后/不要/必须/决定/方案）命中，就把整句写成
`scope:user / kind:semantic / assertedBy:user`；`lifecycle.ts` 随后显示“已确认”。
“这次不要联网，先离线测试”也会进入长期用户记忆。

### 修法
- 新增 `modules/memory/intent.ts`：
  - 临时边界（这次/本次/当前任务/暂时/临时/先…）+ 无长期边界 → `task-constraint` /
    `temporary-instruction`；
  - 长期边界（以后/长期/永久/总是/一直/每次/统一/约定/习惯/偏好…）→ 长期偏好/稳定决策；
  - 只有“决定/采用/方案”无长期边界 → 稳定决策候选（仍需准入）；
  - 只有“不要/必须”无边界 → `candidate`，不自动写长期。
- `classifyUserMessage` 增加意图闸门：只有 `long-term-preference` / `stable-decision`
  才允许自动捕获；临时/候选一律不给自动写。
- `proactive.ts` 对临时约束给一行“这是当前任务约束，不要写成长期记忆；若用户明确要求
  记住请限定失效边界”，而不是“长期偏好”。
- 测试：`这次不要联网，先离线测试` → 不写；`不要用 npm 安装依赖` → candidate；
  `以后回答请简洁` → 长期偏好；`决定统一用 pnpm` → 稳定决策。

## P2：“修复已验证”过度标记

- 字段改名为 `recoveredFromFailure`，展示文案改为 **“失败后再次成功”**；

## P2：主动记忆仍不是自主记忆管理

如实说明：`proactive.ts` 仍是**行动建议**（动态提示），不是强制工作流；模型仍可能
不查重、不正确 supersedes、或保存不适合长期保存的内容。下一步应做有限状态工作流：
候选检测 → 作用域/时效 → 查重/召回 → 写入候选或已确认 → 验证 → 冲突/过期处理；
“用户明确要求记住”可优先执行，其余按证据和作用域处理。本次没有实现该状态机，
避免继续扩大关键词列表。
