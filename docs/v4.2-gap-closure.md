# OMB v4.2 — 留白收尾（AGENTS 指纹 / shell 写 / 跨会话 / 符号层 / 盲写策略）

> 本文件只记录 v4.2 相对 v4.1 的**新增判定与实测**；v4.1 契约仍以
> `docs/v4.1-spacetime.md` 为准。版本：**4.2.0**；构建：见 `build-generation.json`。
> 明确排除：`dsh-path-guard` 的 `selfProtection`（用户设置，本版不动）。

## 0. 为什么做这一版

v4.1 把"读后内容变了"做成了资源级哈希守卫，但仍有五个明确留白（v4.1 交付记录里
逐条列过）。v4.2 把它们收掉，目标不是加功能，而是让**写可见性**覆盖到
"文件工具之外"：shell、其他会话/子代理、规则文件本身。

## 1. 五项变更

### 1.1 指令文件指纹进工作区状态

- `WorkspaceEpoch` 新增 `instructions: string | null`：对 `<cwd>/AGENTS.md`、
  `CLAUDE.md`（≤256KB/个）做 sha256 前 12，合成一个指纹；没有文件 = `null`。
- `turn/start` 时比较上次指纹：真变化才在状态行加 `指令已变`；首次见到只记录。
- 项目画像的入口候选新增 `AGENTS.md`、`CLAUDE.md`（`omb_project` L1 可直接看到）。
- 不把指纹混进 `epoch.id`（宿主 tree id 形状不变），避免改变既有去重语义。

### 1.2 shell 写文件可见性

- 新增可注入端口 `shellTools`（默认 `pwsh/powershell/bash/shell/terminal/cmd`）。
- `extractShellWritePaths(command)`：确定性正则提取重定向（`>`/`>>`）、
  PowerShell `-Path/-LiteralPath/-Destination/-FilePath`、常见 cmdlet 首参、
  `sed -i`、`git checkout/restore` 路径；提取不到但命令带写特征 → `unknown`。
- `tool/call` 时记录 `shellWrites[absPath]=at`（每会话 ≤32），并汇入跨会话写表；
  `unknown` 计 `shellUnknown`（显式未知，不写 0）。
- 守卫：读取时 hash 不可用的文件，若其后有 shell 写 → **deny**（"重读后再编辑"）；
  逃生门不变。shell 成功（post-execute）后把提取到的路径并入 `writeIntent` 归因。
- 状态行可产 `shell 写 N` / `shell 未知写 N`；`omb_project` L2 与 `omb_status` 同步显示。

### 1.3 子代理 / 跨会话写并入归因

- 新增全局有界表 `recentWrites: <cwd>\0<absPath> → {sessionId, at}`（≤256）。
- 文件写成功与 shell 写都会登记；`situation().sideEffects.otherSessionWrites` 统计
  "本会话读过、但之后被其他会话写过"的路径数。
- 守卫：读取时 hash 不可用且被其他会话改过 → deny（理由明确写"其他会话（含子代理）"）。
- 内容哈希仍是主判据；这张表补的是**无法核验时**的保守拒绝与可见性，而不是替代哈希。

### 1.4 符号级 repo-map（结构化，不注入）

- `ProjectProfileSource` 新增 `exports?: number`、`symbols?: readonly string[]`。
- `extractSymbols(text, ext)`：TS/JS `export function/class/const/interface/type/enum`、
  Python `def/class`、Go `func/type`、Rust `pub fn/struct/…`；按出现频次排序取前 6。
- 画像扫描时顺带产出（单文件 ≤512KB、总扫描 ≤2000 文件的上限不变）；
  `omb_project` L1 只展示前两个有符号目录的短摘要（≤ 数十字），不新增常驻提示。
- 边界：正则不是语言服务，不解析导入图/调用关系；深层 repo-map 仍留 v4.3。

### 1.5 盲写策略可配置

- `SessionStateConfig.blindWritePolicy: 'allow' | 'deny'`，默认 `allow`。
- `deny` 时：无读取印记且目标已存在 → 拒绝（计 `denies`），同路径同回合第 3 次
  按逃生门放行（防死锁）。`blindWrites` 两种策略都计数。
- 默认不改，是因为读可能发生在 shell（`Get-Content`/`cat`）里，硬拦会误伤；
  shell 写现在有独立可见性后，需要更严的项目可自行打开 `deny`。

## 2. 判定表增量（叠加在 v4.1 §4 上）

| 情况 | 判定 |
| --- | --- |
| 无印记，文件存在，`blindWritePolicy=deny` | deny（逃生门第 3 次 allow） |
| 印记 hash=null，读后 shell 写过该路径 | deny（"重读后再编辑"） |
| 印记 hash=null，读后其他会话写过该路径 | deny（"其他会话（含子代理）"） |
| 印记 hash=null，无上述写 | allow + `unverifiable`（配额不变） |
| 其他情况 | 同 v4.1 §4 |

## 3. 验收

- 单测：指令指纹"无→有→变"、shell 路径提取、shell 写后 deny、跨会话写 deny、
  盲写 deny 的逃生门；项目画像符号层与 `AGENTS.md` 入口。
- 门禁：`tsc --noEmit` / `eslint .` / `vitest run` / `build` / `check-resolution`。
- 真机：`omb_status` 报 4.2.0 与新构建代；状态行出现「指令已变 / shell 写 / 其他会话写」；
  `omb_project` L1 出现「符号 …」。
