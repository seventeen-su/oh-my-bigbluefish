# OMB v4.15.0 — 管理侧边栏（只读 UI）

> 用户指令第 3 项第一阶段（x2；用户口径：**新界面也只升 x2，只有重构才升 x1**）。
> 目标是把记忆库/状态/候选/审计/冲突从"只能让模型调工具"变成**用户可以直接看的侧边栏**。

## 1. 形态

- 浏览器侧边栏新增 **OMB 记忆** 图标行（`sidebar.panellist`），点开进入主面板
  （`main` keyed slot，`key='omb-memory'`）；
- 三个页签：**概览**（库就绪/打开项目/活跃与候选计数）、**记忆库**（搜索 + 作用域/状态/类型过滤 + 列表 + 详情）、
  **候选确认**（模型推断写入、等待用户确认的条目）；
- 详情面板：逐字正文、标签、来源、阶段（候选/已确认）、确认审计、**可能相关/冲突**
  （共享实体键的活跃条目，判据与 `omb_remember` 的冲突提示同一份 `findRelatedRecords`）；
- 全部只读：确认仍由用户执行 `/omb-confirm <id>`；UI 不写库、不自动 supersede。

## 2. 数据与接线

三层，各自可独立验证：

1. **只读服务** `modules/memory/ui.ts`（内核服务名 `omb:ui`，见 `SERVICES.ui`）：
   `overview()` / `list(query)` / `candidates(limit)` / `detail(id)`；
   数据源是 `StoresService.snapshot()`，不新增库连接、不新增后台任务；
   全部有界（单页 ≤50、候选 ≤20、详情审计 ≤20、扫描 ≤500 行/库）。
2. **宿主路由** `dsh/ui-route.ts`：注册 `webServer` 的 `/omb/api` 前缀：
   `GET /overview`、`GET /list?scope&status&kind&q&tags&limit`、`GET /candidates`、`GET /detail?id`。
   只接受 GET（写请求 405）；跨源 Origin 403；响应 `no-store`；服务缺席 503；
   没有 `webServer` 的宿主不注册（侧边栏自然不出现，不假装可用）。
3. **浏览器 bundle** `packages/memory/client.js`：手写 `window.__ModuleLoader__` 工厂，
   用宿主共享的 React；在 `main` 与 `sidebar.panellist` 注册；页面数据走 `fetch('/omb/api/…')`。
   声明在 `packages/memory/package.json` 的 `dsh.client`（`platform: web`、`immediately: true`），
   不新增组件行——记忆组件本身就是它的宿主。

## 3. 隐私与边界

- UI 是**用户自己打开的页面**：sealed 模式下模型上下文读不到记忆，但用户仍能看自己的库；
  两条通道不互相放宽——模型工具仍走原隐私闸门；
- 路由只在本机回环监听上存在（`webServer` 配置），不暴露给网络；不做账户体系；
- 只读第一阶段：**手动确认/冲突裁决仍走用户命令**；写入口留给下一版（x3），
  并复用同一条服务方法（"一个操作两个调用方"），不在 UI 里另写一套写逻辑；
- 相关条目是**提示**，不是裁决：是否冲突由用户/模型判断，不自动建边、不自动 supersede。
