# OMB v4.14.0 — 主动记忆提示扩展与跟进

> 用户指令第 8 项（x2）：提高模型自主记忆的**主动性**。之前的问题是：
> ① 提示只覆盖"显式要求/纠正/决定/偏好"，最常值得记的**项目事实**（路径/命令/端口/版本/URL）没人提醒；
> ② execute 模式下主动提示被**整体抑制**（让位给控制器），控制器没写时模型完全收不到信号；
> ③ 提示只在当轮有效，命中后没写就消失了，没有第二次机会。

## 1. 新信号

`proactive.ts` 新增两类 cue（确定性正则，热路径零 LLM）：

- `recall-first`：用户引用过去结论（"当时/之前/上次…"）但**没有**明确纠正
  → 先 `omb_recall` 查旧条目，再决定是否更新/supersedes（不冒充更正）；
- `project-fact`：文本含可复现工件（路径/命令/端口/版本/URL）
  → 若会长期有效，用 `omb_remember` 记 semantic（项目库），来源写文件/命令。

优先级：显式要求记住 > 纠正 > 引用历史 > 临时任务约束 > 项目决定 > 长期偏好 >
项目事实 > 不提示。纯问句、闲聊、超长粘贴仍不打扰。

## 2. 两段式提示（不再"控制器一开就不提示"）

`capture.ts` 的 `onUserMessage` 改为：

1. 先算本轮 cue，但**等控制器执行完**再决定是否提示；
2. 若控制器产生了精确提示（旧 id/临时约束等），**提示槽归控制器**（通用 cue 不覆盖）；
3. 若控制器**没有真的写入**（`lastPersistAt !== 本轮`）且没有控制器提示：
   - 给通用 cue 一行（task-constraint 除外——它在 `nudge()` 里有专门且更准确的措辞）；
4. 记录 `pendingCue`；若本轮写入成功则标记 `written`。

## 3. 下一轮跟进（一次性）

若 `pendingCue` 存在且未写入，**下一条用户消息**得到一行跟进：
`上一轮命中记忆信号但未写入：若仍值得记，现在补 omb_remember；不需要就忽略。`

- 只在 `execute` 且偏好捕获未关闭时启用（dry-run/off 没有"本该写"这回事）；
- task-constraint 不进入跟进（它本来就不该写成长期记忆）；
- 只跟进一次：下一轮无论是否写入都会覆盖/清除 pendingCue；
- 回合结束清空提示槽，但**保留** pendingCue 供下一轮判断（不跨进程）。

## 4. 读数

- 活动日志新增 `proactive` 类别（cue 命中 / follow-up）；
- `CaptureStats.proactiveCues` / `cueFollowUps`；健康面只在发生时报
  `主动提示：命中 N 次、跟进 M 次`；metrics 输出 `capture.proactiveCues` / `capture.cueFollowUps`。

## 5. 边界

- 跟进是**提示**，不是自动写入：写不写仍由模型/用户决定；
- cue 判据是确定性正则，不理解语义；宁可漏提示，不把闲聊变成"快写记忆"；
- 控制器精确提示优先，避免同一条内容被 cue 和控制器同时催写。
