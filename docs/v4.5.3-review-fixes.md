# OMB v4.5.3 — 七点审查修复记录

> 范围：用户 2026-10 的七点审查中，**可当场修复的 1–4** 已落地；5–7 是架构方向，
> 本文只写清方向和验收判据，**不声称已完成**（`AGENTS.md` 的"不要在文档里假装已做"）。

## 1. 依赖关闭后的状态面

**现象**：微内核关闭时，其它模块在宿主插件页显示"等待依赖"；关闭记忆库时，
用户画像等模块在 `omb_status` 里仍显示"运行中"。

**根因（两条叠加）**：

- `omb_status` 的模块行读的是内核健康面里**最近一次上报的快照**
  （`kernel/health.ts`），依赖被关闭后模块通常不会再上报；
- 画像的 `ProfileStorage.availability()` 先读 `#lastResolve` 缓存，
  记忆库已卸载时仍可能返回旧的 `{ ok: true }`。

**修法**：

- `dsh/status-tool.ts`：渲染模块行时读 `moduleGraph().missingDependencies`（内核账本现算），
  依赖未挂载的模块一律按 `degraded` 展示，并写明缺的是谁、为什么（前置被宿主卸载）。
  这覆盖画像、制品、向量等所有声明了 `requires` 的模块，不依赖各自再上报一次。
- `modules/profile/storage.ts`：`availability()` **先探服务再看缓存**；
  `kernel.service('stores')` 取不到立即降级，缓存只能描述"上一次取库结果"。

**边界（如实说）**：宿主插件页那一行是否显示"等待依赖"由宿主 fiber 状态决定，
OMB 不能改宿主的页面；OMB 能保证的是**自己的状态面不再谎报运行中**。

## 2. `scripts/heap-snapshot.ps1` 与进程内快照

### 2.1 `NODE_OPTIONS`

旧脚本用一行字符串整体覆盖，会丢掉用户原有的其他 Node 参数。现在：

- 按引号/空白分词，保留全部非冲突参数；
- `--max-old-space-size` / `--max_old_space_size` 与 `--heapsnapshot-near-heap-limit`
  单独识别并**显式打印冲突处理**；
- `repro` 模式保留原堆上限，只追加 near-limit 快照开关；
- `early` 模式移除原堆上限并替换为 `-HeapMB`，同时打印"改变了原始故障条件"；
- 退出/异常时恢复原 `NODE_OPTIONS`（原值为空则删除变量）。

### 2.2 快照来源 PID

- 脚本启动前打印"`NODE_OPTIONS` 会被子 Node 进程继承"；
- 运行后扫描新生成的 `.heapsnapshot`，从文件名解析 PID；
- 用 `Get-CimInstance Win32_Process` 读该 PID 的命令行，判断是否含
  `dsh`/`bin.ts` 与 `web`；不是主宿主进程时明确警告"子进程 retained set 不能代表宿主"；
- 进程已退出（OOM 后常见）时如实说"无法核对职责"，不假装已确认。

### 2.3 两种模式不可混用

- `repro`：原始故障复现，保留原堆上限，只加 near-limit 快照；
- `early`：主动降低堆上限，提高取证成功率，但**数据不等价于原始 4GB OOM**。

### 2.4 磁盘、保留与隐私

- 启动前检查快照目录可用空间（默认最低 4GB），不足直接拒绝；
- 运行后只保留最近 `-Keep` 份（默认 3）；
- 进程内的 `/omb-heap snapshot` 与 `omb_status({ snapshot: true })`
  统一走 `dsh/heap-snapshot.ts`：同样的空间检查、保留策略、隐私提示；
- 快照被定义为**敏感诊断材料**（含提示词、会话内容、路径），提示不要提交/公开分享。

## 3. 自主捕获：没有结果就不写"完成"

旧降级路径：宿主事件没有 `callId` 时，`tool/call` 直接写活动记录并计
`unconfirmed-call`——计数可见，但正文与成功记录相同，仍是"尝试过被记成完成过"。

现在：

- 无 `callId` 也只挂 pending，键由 `tool+args` 派生（`fallback:<hash>`）；
- 结果事件带同样的 `tool+args` 才能配对，配对后才写；
- 结果既无 `callId` 也无法判定属于哪条调用 → 计 `unknownCorrelation`，不写；
- 回合结束仍未配对 → 计 `unconfirmed`，不写；
- `unconfirmedCall` 的含义改为"这条调用缺少宿主关联 ID"，不再表示"已写入"。

仍待宿主改进：提供可靠的调用关联 ID（`callId`）应作为首选；派生键只是兜底。

## 4. 写守卫

已修：

- `dsh/plugin.ts` 的旧注释（"只 deny edit、write 只警告；第 3 次放行"）删除，
  改为与状态机一致的描述；
- `blindWritePolicy` 默认从 `allow` 改为 `deny`：覆盖已存在文件且无读取印记 → 拒绝；
- 连续 deny 到阈值后**不再自动放行**。放行条件是"最近一次 deny 之后产生过新的读取印记"，
  即模型确实重读并重建补丁；`gaveUps` 记录的是这种重读授权次数；
- 保留"新建文件直接 allow"与"守卫自身异常 fail-open"，避免把守卫变成不可恢复的死锁。

**仍不能保证的**：`tools/pre-execute` 的哈希校验与宿主真正写入不是原子操作；
用户恰好在两者之间修改文件，仍有竞态窗口。要真正消除，需要宿主侧"打开-校验-写"
原子接口或独立 git worktree 隔离编辑，这不是 OMB 单方面能声称解决的。

## 5–7. 方向与已落地的第一刀（不声称全部完成）

### 5. 项目地图与真实结果闭环（未完成）

现状是有界静态扫描 + 近似调用边，**不是编译器级调用图**。下一步不增加边数，而是：

- 把构建/测试/故障复现/已验证修复的结果作为画像的"证据层"；
- 每条证据带命令、退出码、时间、来源路径；
- 地图中的节点只有关联到真实结果，才标"已验证"。

验收：`omb_project` 能指出"这个模块最近一次通过的测试命令与失败复现"，而不是只有导入边。

### 6. 统一知识生命周期（已落地第一道闸门，未完成全链）

层级不是重点，**层级之间不能自动晋升**才是。v4.5.3 已在 `omb_remember` 落一道
结构性闸门（`decideLifecycle`）：

- `execution-confirmed`（一次工具调用/执行结果）**不能**直接写成 `procedural`
  可复用经验；会被降级为 `episodic` 事件并在回执里说明"路由已调整"；
- `semantic` 仍可由用户陈述、可复现工件或执行台账准入（纯模型推断没有 ground，过不了准入）；
- 原始 `episodic` 永远可写（保留事实，不保留未经确认的层级）。

仍未做：完整的 `event → candidate → confirmed → experience` 持久状态与
"重复验证/用户确认"升级路径；当前只拦了最危险的一条自动晋升。

验收（下一阶段）：每条 `confirmed`/`experience` 都能回溯到证据；没有证据的条目停在 `candidate`。

### 7. 检索优化有效命中（已落地测量，未完成排序评估）

v4.5.3 在记忆健康面给出**有效命中**读数：

- `retrieval.exposed`：召回曝光条数；
- `retrieval.used`：曝光后 `used_tool` 实体键命中的条数；
- `retrieval.effectiveRate = used / exposed`（`exposed=0` 时不给 "0%"，明确是"暂无读数"）；
- detail 行写明"有效命中 used/exposed"，不把检索次数当命中率。

排序侧已有 `utility`（Beta 后验 + 收缩）替代旧 `useCount/(1+useCount)`；
仍未做：precision@k、重复命中率、按有效命中的对照实验与自动调参。

验收（下一阶段）：状态面能给出"有效命中/总检索"，排序改动有对照数据。
