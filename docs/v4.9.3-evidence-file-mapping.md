# OMB v4.9.3 — 项目证据到文件映射

> 既有"项目运行证据"的细化（x3）：证据原来只说"最近一次测试过没过"，
> 不回答"这次测试覆盖了哪些文件"。本版从命令行里抽文件路径，随证据落盘，
> 并在 `omb_project` L1 与证据并排显示。

## 1. 为什么需要

`dsh/project-evidence.ts` 记录的是命令级事实：`pnpm test`、`npx tsc --noEmit`。
但同一个项目里"哪个文件的测试过了"才决定证据可用不可用：

- 命令被截断显示（L1 只显示 28 字符）时，看不到它覆盖的文件；
- 换了一组测试文件跑，证据同样是"测试✅"，语义却不同；
- 没有文件映射，就无法回答"这个文件的最近验证是什么时候"。

## 2. 做法（确定性、零解析器）

`extractEvidencePaths(command)`：

- 支持：相对路径（`tests/a.test.ts` / `./src/a.ts`）、Windows 绝对路径
  （`C:\repo\src\a.ts`）、带扩展名的裸路径（`modules/memory/store.ts`）；
- 排除：URL（`https://…` 先剥离，不映射成文件）、目录、包名、符号；
- 去重、按出现顺序、单条最多 `MAX_EVIDENCE_PATHS`（5）个；
- 抽不出来就**不写** `paths`（不猜"大概是哪个文件"）。

证据落盘格式升到 **v3**：`paths` 随条目写入 `.omb/evidence.json`；
v2 旧文件照常读取（路径缺省），v1 仍把所有结论降为 `unknown`。
读取时对 `paths` 做类型过滤与截断（旧文件/手改文件不会把畸形值带进状态面）。

## 3. 展示

`omb_project` L1 的证据行在每条证据后追加文件映射：

```
证据：测试✅ pnpm test … 2 分钟前 → tests/modules/memory/store.test.ts、src/a.ts
```

- 最多显示 2 个路径（各 36 字符），更多写"等 N 个"；
- `renderProjectEvidence` 仍遵守三种说法：未接线 / 本进程暂无读数 / 有读数；
- 路径只来自命令文本，不是"本次真的改了/测了哪些文件"——**不声称覆盖范围**。

## 4. 明确边界

1. **不解析符号**：函数/类级映射需要类型解析，本版只到文件；
2. 命令里没写文件（如 `pnpm test` 跑全量）就没有 `paths`，不会猜全仓库；
3. 路径大小写/分隔符按解析结果保留（Windows 路径统一为正斜杠），不做真实存在性核验
   （证据是"命令提到过"，不是"文件被访问过"）；
4. 只影响 L1 展示与落盘字段，不改变任何写入/召回路径。
