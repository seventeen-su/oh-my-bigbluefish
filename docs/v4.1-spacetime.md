# OMB v4.1 — 时空坐标（Spacetime）分层规格

> 本文件是 v4.1 的**实现契约**：接口、判定表、验收条件。事实优先于叙述。
> 提交基线：`18ec311`（v4.0.0 / g88）。目标版本：**4.1.0 / g89**。

## 0. 为什么

v4.0 已有四个各自正确的组件：项目画像、会话状态机、记忆库、推理技能。但它们
**各自回答半句话**：

- 项目画像知道"仓库有什么"，不知道"这个会话现在在哪、离上次过了多久"；
- 状态机知道"epoch 变了、读印记旧了"，不知道"这个仓库是什么、值不值得看"；
- 记忆库知道"以前记过什么"，但项目身份按 cwd 切分，子目录会话另起一个库；
- 自主捕获在 tool/call 时就写"编辑文件：x"——**尝试过**被记成**完成过**。

v4.1 的目标不是再加一个工具，而是让四者共享**同一套坐标**：一次 `omb_project`
调用给出 L0–L5 六层事实；状态行只给增量；写守卫用资源级内容哈希；记忆按项目根统一。

## 1. 三维定义

| 轴 | 含义 | 事实来源 |
| --- | --- | --- |
| 空间（Space） | 项目根 → 目录 → 文件 → 资源版本 | `project-root` / `project-profile` / 读取印记的 `hash` |
| 时间（Time） | 提交历史 → 工作区 epoch → 回合/步 → 空闲间隔 → 记忆 `observedAt/validTo` | `state-machine` / git / 记忆库 |
| 状态（State） | 读印记、写意图、外部改动、目标待办、记忆关联边 | `state-machine` / `link` 图 |

## 2. 六层输出（`omb_project`，总长 ≤ 2400 字符）

| 层 | 内容 | 缺失时 |
| --- | --- | --- |
| L0 身份 | name/version、git root、cwd 相对根、branch/head/headAt | 写"非 git/未接线" |
| L1 结构 | 顶层目录、源码目录（文件数/行数/测试数）、入口文件、docs 标题、构建命令 | 写"画像不可用（不是空）" |
| L2 空间状态 | epoch id、脏文件数、外部改动数、读取印记数（已变化数/无法核验数） | 写"状态未知" |
| L3 时间 | 回合/步、空闲档位与间隔、上次回合结束原因、是否中断 | 写"无会话归属" |
| L4 知识 | 项目记忆 top 3（时间、类型、摘要）、项目记忆近况、关联边数量 | 写"暂无记忆" |
| L5 意图 | 开放目标/待办、未解决标记 | 写 0（这是真的 0，不是未知） |

渲染顺序固定、每层一行标题；同一输入产出同一文本（记忆与状态变化除外）。

## 3. 服务与形状

### 3.1 `SERVICES.projectRoot = 'omb:project-root'`（新增）

```ts
interface ProjectRootPort { resolve(cwd: string): string }
```

- 由 `dsh/project-root.ts` 实现：`git -C <cwd> rev-parse --show-toplevel`，同步、2.5s 超时；
- 缓存 `cwd → root`，TTL 60s，上界 128；失败返回 `cwd` 本身（不抛）；
- 非 git 目录：返回规范化 cwd（与 `projectIdentity` 同义）。

### 3.2 `SERVICES.projectProfile`（升级，名字不变）

```ts
interface ProjectProfileView {
  readonly text: string              // 兼容旧消费者，≤1400 字符
  readonly generatedAt: number
  readonly gitHead?: string
  readonly root?: string             // git root（非 git=cwd）
  readonly cwdRel?: string           // 本次 cwd 相对 root；根目录为 ''
  readonly identity?: { name?: string; version?: string; branch?: string; head?: string; headAt?: number }
  readonly structure?: {
    topDirs?: readonly { name: string; files: number }[]
    sources?: readonly { dir: string; files: number; lines: number; tests: number }[]
    entries?: readonly string[]
    docs?: readonly { path: string; title: string }[]
  }
  readonly history?: { commits?: readonly { hash: string; subject: string; at: number }[]; dirty?: number }
  readonly gates?: readonly { name: string; command: string }[]
}
```

- 构建发生在 **git root**；`cwdRel` 是本次调用目录相对根的路径（保留"我在哪"）；
- 缓存 key 仍为 cwd（上界 32，TTL 10 分钟）；同一 root 不同 cwd 可各有一份，但结构相同；
- 源码目录扫描有界：跳过 `node_modules/.git/lib-gen/dist/build/coverage/.omb` 等，最多 2000 个文件；
- 全部确定性（排序固定）、绝不抛、单段失败只丢该段。

### 3.3 `SERVICES.sessionState`（升级）

```ts
interface ReadStamp {
  readonly path: string          // 调用方给的归一化路径
  readonly absPath: string       // 绝对路径（哈希与守卫使用）
  readonly at: number
  readonly step: number
  readonly epochId: string
  readonly via: 'fs'
  readonly hash: string | null   // sha256 前 16；null=目录/超限/读失败
  readonly size: number | null
}

interface SessionSituation {
  readonly sessionId: string
  readonly cwd: string | null
  readonly state: SessionState
  readonly tier: IdleTier
  readonly turn: number
  readonly step: number
  readonly lastEventAt: number | null
  readonly idleMs: number | null
  readonly lastTurnEndReason: string | null
  readonly interrupted: boolean
  readonly unresolved: boolean
  readonly goals: { readonly open: number; readonly total: number }
  readonly todos: { readonly open: number; readonly total: number }
  readonly epoch: SessionStateSnapshot['epoch']
  readonly reads: {
    readonly count: number
    readonly changed: number
    readonly unknown: number
    readonly entries: readonly { path: string; status: 'same' | 'changed' | 'unknown'; hash: string | null }[]
  }
  readonly sideEffects: {
    blindWrites: number; staleWrites: number; denies: number; gaveUps: number
    writeWarnings: number; unverifiable: number
  }
}

interface SessionStateService {
  // 既有方法不变
  situation(sessionId: string): SessionSituation | undefined
}
```

`situation()` 只读、同步、绝不抛；`entries` 按 path 排序、最多 16 条。

### 3.4 `createProjectTool`（升级）

新增依赖（全部可选，缺省降级）：

```ts
readonly situation?: (sessionId?: string) => SessionSituationView | undefined
readonly privacyAllowsRead?: (sessionId: string) => boolean
readonly projectRoot?: (cwd: string) => string
```

- `sealed` / 解析失败：**不读画像、不读记忆**，返回一句可读原因；
- 无会话归属：只允许画像（不读记忆），并在文中写明"无会话归属"；
- `read-only`：读画像与记忆都允许（写由 store 闸门另行拒绝）。

### 3.5 `modules/memory/capture.ts`（生命周期）

`tool/call` → `pending`（按 callId）；`tool/result` 决定写什么：

| 结果 | 写入 |
| --- | --- |
| `ok === true` | `执行命令：…` / `编辑文件：…`（旧文本） |
| `ok === false` | `未生效：执行命令：…` / `未生效：编辑文件：…` |
| `ok === undefined` | 不写，计 `unknown-result` |
| 无匹配 pending | 计 `no-pending` |

- pending 有界：每会话 20、全局 512；`turn/end` 未解决 → 丢弃并计 `unconfirmed`；
- 无 callId 时退回旧行为（call 时写）并计 `unconfirmed-call`，这是**明确记录的降级**；
- 统计新增 `failed` / `unconfirmed` / `unknownResult` 计数，进 `omb_status` 记忆段。

### 3.6 项目身份统一（记忆库）

- `StoresServiceOptions.projectRootOf?: (cwd) => string`；
- `ensureProject` / `forProject` / `peek` 一律先解析项目根，再 `projectIdentity(root)`；
- `projectScope`（→ `omb_project` 的 store 与记忆 `project` 字段）= 项目根；
- 子目录会话与根会话共享同一个项目库；非 git 目录退化为 cwd。

## 4. 写守卫判定表（`guardEdit` 语义扩展为 edit+write）

| 情况 | 判定 | 记账 |
| --- | --- | --- |
| 无印记，目标文件不存在 | allow | — |
| 无印记，目标文件存在 | allow | `blindWrites++`（未保护） |
| 印记 `hash === null` | allow | `unverifiable++` |
| 当前内容读不到/超限 | allow | `unverifiable++` |
| `hash` 相同 | allow | — |
| `hash` 不同（读后被改） | **deny**（≤120 字符事实句） | `denies++`；同路径同回合第 3 次 allow 并 `gaveUps++` |
| 守卫内部异常 | allow | 日志（fail-open，不成为单点故障） |

- 路径一律 `resolve(cwd, path)`；Windows 大小写按实际路径比较，不额外小写；
- 读工具命中 `config.readTools`（默认 `read`/`read_file`）时计算内容哈希，单文件上限 **2MB**；
- `tools/post-execute` 成功（`result.isError === false`）后重算该文件哈希并刷新印记——
  **自己的写不误伤自己**；失败不刷新；
- `writeIntent` 在 `turn/start` 边界清空；post-execute 成功时加入（归因用）。

## 5. 隐私

- `omb_project` 在读取前调用 `SERVICES.privacy.decide(sessionId)`；
- `allowRead=false` → 拒绝画像与记忆（sealed 的语义不能只落在库边界，因为画像不经过库）；
- 测试必须覆盖：sealed 全拒、read-only 允许读、归属未知只给画像、隐私服务缺席时可读。

## 6. 不变量

1. 热路径零 LLM：守卫、捕获、画像、situation 都不调用模型；
2. 确定性：同一文件树/同一事件序列 → 同一结论；
3. 绝不抛：所有新增路径 try/catch，失败只留声与计数；
4. 有界：stamps 64、pending 20/会话、画像缓存 32、situation entries 16；
5. 未测量 ≠ 0：缺服务/缺会话要写"未接线/无会话归属"，不得写成 0 或绿。

## 7. 验收

- 单测逐行覆盖第 4 节判定表与第 3.6 节身份统一；
- 捕获测试：失败调用写"未生效"，成功写旧文本，未配对不写；
- `omb_project` 测试：sealed 拒绝、六层顺序、缺服务降级；
- 门禁：`npx tsc --noEmit`、`npx eslint .`、`npx vitest run` 全绿；`node scripts/build.mjs` 产 g89；
- 真机：重启后 `omb_status` 报 4.1.0 / g89；`omb_project` 返回六层；守卫在"读后被外部改"时 deny。

## 8. 本版明确不做（不假装）

- 文件符号级 repo-map（函数/类调用图）：需要语言服务，收益未验证，留给 v4.2；
- 三方合并/新补丁生成：守卫只做"读后已被改 → 拒绝并让模型重读"；
- shell 写文件的追踪：`pwsh` 副作用仍是盲区，状态面如实计数；
- 子代理写集并入、AGENTS.md 指纹：未实现。
