# OMB v4.10.1 — 取消离线整合，改为写入时确定性去重

> 用户指令第 4 项（x3）：**取消每 32 回合的离线整合**这种低质量方式，
> 把去重责任放到**写入时**，用确定性判据完成。

## 1. 删掉了什么

- `modules/memory/consolidate.ts` 整个模块（`planConsolidation` / `decayPrior` /
  近似重复 0.7 合并 / 自动 `supersedes` / 自动 `conflicts_with` 边）；
- `modules/memory/index.ts` 的 `turn/end` 订阅、`consolidationEveryTurns` 配置、
  整合台账与健康面读数、`CONSOLIDATION_SCAN_LIMIT`；
- `cordis.patch.yml` 的 `consolidationEveryTurns: 32`；
- 对应测试（`tests/modules/retrieval/consolidate.test.ts`、
  `tests/modules/memory/consolidation-wiring.test.ts`）与配置断言。

为什么删：0.7 的 Jaccard 近似合并会把"同一主题的另一面"当成重复并自动标失效，
这是**有损且不可解释**的；用户看到的是旧结论莫名消失，而不是"被谁取代"。

## 2. 写入时的确定性去重（保留并明确）

判据在 `remember.ts`，控制器捕获、`omb_remember`、重复捕获共用**同一份**：

1. **逐字同内容**：`contentHash` 精确命中 → 不新增，回执给出既有条目 id/阶段；
2. **近似同内容**：归一化（NFKC、去空白/标点、小写）后字符 bigram Dice ≥ 0.9
   → 视为同一条；回执写明相似度与匹配方式；
3. **数字保护**：归一化后的数字串不同（`8080`/`8081`、`case-0`/`case-1`）一律不算近似
   ——端口、版本、序号是事实，不是排版差异；
4. **用户断言升级**：本次 `assertedBy=user` 命中既有候选/事件 → 就地改
   `assertedBy:user`（正文/id/sourceRef/observedAt 一字不改），回执"已升级"；
5. **不自动标失效**：写入路径只插入；是否 `supersedes` 由调用方显式给出
   （`omb_remember` 的 `supersedes` 参数），非破坏、历史可查。

判据是**纯函数 + SQL 查询**，没有时间窗、没有后台任务、没有阈值漂移：
同输入永远得到同结论（数字保护与 0.9 门槛都是常量）。

## 3. 代价与边界

- 没有后台整合后，**历史里已经存在的近似重复**不会被自动清理；它们仍是独立条目，
  需要用户/模型用 `supersedes` 显式更正（这是有意的：不静默合并两份原文）；
- 近似判据只到 0.9：改写幅度更大的两条不会被当成同一条（逐字保真优先）；
- 不再生成 `conflicts_with` 自动边；冲突提示仍由 v4.9.0 的只读回执承担；
- 健康面不再有"离线整合"读数（不再有这件事，不报 0 次假装它在跑）。
