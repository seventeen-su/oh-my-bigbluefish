# OMB v4.17.0 — OMB 设置：二级侧边栏、动效、会话隐私页

> 用户六点要求：
> ① 响应式 + 弹性布局；② 二级侧边栏而非顶部菜单栏；③ 应用 DSH 标准控件；
> ④ 适当优雅动效（如未选中内容时右侧详情栏收起）；⑤ 排查"部分会话命令消失一部分"；
> ⑥ 标题改为「OMB 设置」，并新增管理各会话隐私模式的子页。

版本 **4.17.0（x2）**：新界面按用户口径只升 x2，不升 x1。

## 1. 二级侧边栏与弹性排版

面板结构改为「标题栏 + 左侧导航轨 + 右侧内容」：

- **二级侧边栏**：`.omb-nav` 是 `nav`（`aria-label="OMB 设置导航"`），六个
  `button`（`aria-current="page"`）——概览 / 记忆库 / 候选确认 / 会话隐私 /
  运行状态 / 项目画像；顶部 `SegmentedTabs` 主导航**移除**（用户要求不再用顶部菜单栏）。
- **响应式**：面板自己是容器（`.omb-page { container-type: inline-size; container-name: omb-panel }`）：
  - 容器 < 720px：导航轨 46px、只显示图标（`title` 提供悬停文字）；
  - ≥ 720px：导航轨 172px、图标 + 文字；
  - ≥ 900px：记忆库/候选页的列表与详情**并排**（`flex-direction: row`）；
  - 窄容器：详情是覆盖在列表上的滑入面板；`@media (pointer: coarse)` 放大点击目标。
- **弹性**：卡片 `grid-template-columns: repeat(auto-fit, minmax(min(180px, 100%), 1fr))`；
  所有列表/内容容器 `min-width:0`、`flex:1 1 auto`；长文本 `overflow-wrap:anywhere`；
  页面与列表/详情各自 `min-height:0` 独立滚动，不产生横向滚动。
- **标准控件**：`Button`/`Input`/`Pill`/`Tag`/`SegmentedControl`/`StateDot` 与
  标准图标（`IconGaugeOutlineRegular` 等）全部来自共享基线
  `@deepseek-ai/dsh-client-ui-primitives`；颜色/圆角/焦点环走 `--dsw-*` token，
  测试断言无十六进制色值。

## 2. 动效（可核对形式）

| 场景 | 机制 | 时长/曲线 |
| --- | --- | --- |
| 页面切换 | 关键帧淡入 + 上移 4px（`.omb-page-in`） | 160ms `--ds-ease-in-out` |
| 详情栏展开/收起（宽容器） | `flex-basis` 0 → 56% + `opacity` + `translateX(8px)` | 220ms / 180ms `--ds-ease-in-out` |
| 详情面板滑入（窄容器） | `position:absolute` + `translateX(100%)` → 0，`visibility` 延时切换 | 220ms |
| 导航/列表 hover | `background-color` / `border-color` 过渡 | 100–120ms ease |

**未选中条目时详情栏收起**：`data-detail="closed"` 时详情面板宽度 0、`opacity:0`、
`visibility:hidden`，同时加 `inert`（不可聚焦）与 `aria-hidden`；选中后才展开。
窄容器下点行打开滑入面板，关闭按钮 / Escape / 再次点同行都会收起。

**减弱动效**：`@media (prefers-reduced-motion: reduce)` 下取消位移/淡入与宽度过渡
（状态、颜色、边界仍保留）——去掉的是运动，不是可辨识的状态反馈。这里直接写
`transition: none` 是安全的：收起/展开完全由 React 状态驱动，**没有**任何代码等
`transitionend` 收尾（motion-transitions §8 的例外条件不成立），代码里有对应注释。

## 2.1 界面打磨（本轮追加）

- **品牌头**：图标块 + 标题 + 副标题 + 右侧实时状态点（就绪/未就绪/读数不可用），
  头部下方 0.5px 分隔线；内容区最宽 1120px 居中，超宽窗口不把行拉散。
- **二级导航**：宽容器显示条目计数（记忆库活跃数 / 候选数），图标轨收起文字时
  靠页头标题与 `title` 仍能定位。
- **每页页头**：标题 + 一句话说明（概览/记忆库/候选/隐私/运行/画像各自不同），
  避免图标轨状态下"不知道当前在哪一页"。
- **概览快捷入口**：记忆库 / 候选确认 / 会话隐私 / 运行状态四个跳转按钮。
- **加载与空状态**：加载走标准 `TextShimmer`（不再是一行静态"读取中"）；空列表用
  虚线容器 + 图标 + 标题 + 建议（"清空搜索/切换状态/换作用域"），不是一行冷文字。
- **卡片材质**：与 DSH 设置页同源 token（`--dsw-alias-settings-card-fill` /
  `--dsw-alias-settings-card-stroke`），深浅色由主题给。
- **隐私页反馈与危险操作**：操作结果放到页面顶部通知条（`StateDot` + 文案 +
  `aria-live`）；"清理已结束会话/解除 fail-closed"改用标准 `Modal` 二次确认。
- **闪帧与错误态**：首屏 `loading` 初始为 true，不再先闪"暂无数据"；详情返回 404
  显示"未找到该条目"友好空态；详情等待首帧不发 `id` 为空以外的请求。
- **隐私操作安全**：分段控件首屏显示当前会话真实档位（不默认 read-only，避免误点
  把 sealed 放宽）；按会话 id 设置限制 200 字符；失败时关闭确认框，错误文案可见。

## 3. 会话隐私子页（新数据面）

标题从「OMB 记忆」改为「**OMB 设置**」（面板 `label` 与 `h2` 同一处 `TITLE`）。

页面内容：基线档 / 当前会话解析（显式 / 继承 / 基线 / fail-closed）/ 状态文件
可读写与最近写入时间 / 受限会话（活跃 + 历史，`null` = 未测量不写 0）/
当前会话一键设置 / 按会话 id 设置 / 显式设置列表（活跃/已结束、继承来源、父会话）/
危险操作（清理已结束会话、解除 fail-closed 兜底，均二次确认）/ 命令面与拒绝计数。

数据面契约（`modules/memory/privacy/contract.ts`，类型名与字段已冻结）：

- `UiPrivacyView`：`available`、`reason?`、`baseline{mode,origin,detail}`、
  `current{sessionId,mode,origin,inheritedFrom,detail,parentSessionId}|null`、
  `sessions[]`（`active`、`parentSessionId`、`inheritanceSource`）、
  `restricted{history,active}|null`、`durable{path,ok,detail,savedAt}`、
  `commands{privacy,clean,state}`、`stats`；
- `PrivacyAdminPort`：`view / setMode / clear / clearInactive / trust`（同步、绝不抛）；
- `omb:ui` 增加 `privacy()` 与 `privacyAct()`；未接线/异常返回**完整形状**降级视图
  （不白屏、不把"未接线"渲染成"0 条设置"）。

HTTP（`dsh/ui-route.ts`，仍然只有用户点击能触发写）：

- `GET /omb/api/privacy` → `ui.privacy()`；
- `POST /omb/api/privacy`：
  - `{action:'set', sessionId, mode:'normal'|'read-only'|'sealed'}`
  - `{action:'clear', sessionId}`
  - `{action:'clear-inactive'}`
  - `{action:'trust'}`（仅基线处于 fail-closed 粘性标记时有意义）
  - 参数非法 → 400；业务拒绝 → 409；成功 → 200 `{ok,text}`；
- 同源检查、`no-store`、415（非 JSON）、4KB 上限不变；**没有模型工具入口**：
  隐私是用户的决定，模型不能通过任何工具或端点放宽自己的限制。

语义上复用既有判据，不新增旁路：

- 设置走 `PrivacyCommandApi.setMode`（与 `/omb-privacy` 同一实现），写后持久化；
- 清除走 `/omb-privacy forget` 同一实现；批量清理只动"已结束且不是活跃会话继承来源"的记录；
- **批量清理也把宿主「当前会话」当活跃**（即使它还没有 turn 观测）：否则刚在设置页
  设好的档位可能被"清理已结束会话"顺手放宽；设置页的 `active` 展示用同一判据，
  行里同时显示设置时间；
- 活跃会话的继承来源被清除会放宽正在运行的子会话，页面明确提示，不替用户决定；
- `active` 判据来自 `PrivacyState.isActive()`（本进程内真的活跃过），不是"状态文件里有记录"。

## 4. 第 5 点根因：命令消失不在 DSH 日志里，是客户端菜单规则

用户报告"部分会话的命令会消失一部分：OMB 一系列 + 原装目标/计划/反馈等"。
排查结论：**不是 OMB 注册失败，也不是会话级 catalog 缺失**，而是 DSH Web 客户端的
斜杠菜单规则——**带 `input`（参数提示）的命令只在 `/` 位于草稿最前面（leading）时显示**：

- `packages/client/ui-commands/src/client/service.ts:248`：
  `const visible = rows.filter(c => req.position === 'leading' || c.hint === undefined)`
- `packages/client/ui-input-trigger/src/core/detect.ts:57,71`：
  `position = draft.search(/\S/) === triggerIndex ? 'leading' : 'inline'`
- 输入框上的「+」菜单同样按草稿前缀算 `position`：
  `packages/client/ui-conversation/src/client/apply.ts:543`；
- 该行为有测试钉住：`packages/client/ui-commands/tests/service.client.spec.ts:298`
  `hides leadingInput commands at inline position`。

消失集合正好等于**声明了 `input.hint` 的命令**：

| 命令 | input.hint | inline 时可见 |
| --- | --- | --- |
| `/omb-privacy`、`/omb-privacy-clean`、`/omb-confirm`、`/omb-feedback`、`/omb-depth`、`/omb-heap` | 有 | 否 |
| `/goal`、`/plan`、`/feedback`（原装） | 有 | 否 |
| `/compact`、`/export`（无参数） | 无 | 是 |
| `/file`、`/model`（客户端贡献） | 无 | 是 |

所以"部分会话"实际是"**草稿里 `/` 前面已有文字**（包括上一行文字、残留草稿、命令 chip）
的会话/时刻"：此时带参数的命令被静默过滤，只剩无参数命令。日志侧佐证：
DSH 启动日志只有 2026-10-18 的 `EADDRINUSE 127.0.0.1:3080`（旧进程占用，与命令无关）；
会话日志里 OMB 命令确实执行过（本机实测 `/omb-privacy` 8 次、`/omb-depth` 1 次、
`/omb-heap` 2 次、`/omb-feedback` 1 次），说明**注册与执行都正常，问题只在菜单可见性**。

可用性建议（本轮未改 DSH 源码）：把 `/` 放在空草稿的最前面，或先清空/全选草稿再输入；
直接完整输入 `/命令 参数` 后按 Enter 仍会执行（Enter 认领不检查 leading）。
若希望菜单在 inline 也显示带参数命令，需要改 DSH 客户端这一行过滤规则并重建 Web 客户端——
那是 DSH 仓库的改动，不在 OMB 本版范围内。
