## 2. rc.3 之后仍然会"静默读错"的四件事

### 2.1 母子会话判据：`origin === 'subagent'`（行为错误，已修）

- 宿主把 `SessionHeader.parentSession` 的含义**收窄**了：现在它是"子代理会话的直接创建者"，
  **普通 fork 不再写**；历史普通 fork 可能残留父 id。判据改为 `origin`：
  `packages/core/session/src/types.ts:105-125`（`parentSession` 注释与 `origin?: 'subagent'`）。
- 宿主自己的用法同一条：`packages/api/session-controller/src/archived-session-gate.ts:50`、
  `src/client/sessions/lineage.ts:64`（`s.origin === 'subagent' && s.parentSessionId !== undefined`）。
- **OMB 旧行为**：项目页把任何 `parentSession` 都当父子 → 普通 fork 被错标"子会话"、
  折叠到不存在的母会话下、右侧缩进错位。**修法**：`dsh/session-catalog.ts` 新增
  `parentIdOf(header)`，只有 `origin === 'subagent'` 才返回父 id；持久化与活会话两条路
  共用它。缺 `origin` 的旧子代理会话也按宿主规则不再缩进。
- 护栏：`tests/dsh/session-catalog.test.ts` 新增"普通 fork 残留父 id 不算子会话"用例。

### 2.2 主题 token 被删（视觉错误，已修）

- `--dsw-specific-sidebar-nav-item-hover` 在 rc.3 的 `design-platform.css` 里存在
  （`packages/client/ui-theme/src/styles/design-platform.css:278,396`），**当前宿主线已删除**；
  宿主自己的导航 hover 改用 `--dsw-alias-interactive-bg-hover`
  （`packages/client/ui-settings-general/src/client/SettingsRoot.module.css` 的 `.navCell:hover`、
  `packages/client/ui-sidebar/src/client/SidebarRoot.module.css:343-344`）。
- OMB 的 `.omb-nav-cell:hover` 直接引用旧 token → 解析不到、hover 变透明。
  **修法**：改用 `var(--dsw-alias-interactive-bg-hover)`；`tests/dsh/ui-bundle.test.ts`
  同时断言旧 token 不再出现。

### 2.3 投影读取被标记 deprecated（未来会消失，已跟进）

- `sessionProjections.stateOf(session, key)` 仍返回宿主 state，但 rc.3 起每个键打一次警告，
  文档指向 `handle.stateOf(session)` 或所属域服务
  （`packages/session/session-projection/src/index.ts:421-427`）。
- 第三方插件没有注册句柄，所以 `dsh/pressure.ts` 改为**优先**
  `sessionProjections.snapshot(session, [key]).values[key]`（client wire view），
  没有 `snapshot` 的旧宿主退回 `stateOf`（宿主 state）。解析同时吃两种形状：
  pressure 用 `projectedTokens` 或三字段公式；usage 用扁平 totals 或 `{totals,last}`；
  breakdown 用扁平或嵌套 `breakdown`。
- 护栏：`tests/dsh/pressure.test.ts` 新增 snapshot wire view 用例（与旧 state 用例并存）。

### 2.4 预设里的两处委派行（用户已紧急修复，本轮补测试）

- `@deepseek-ai/dsh-tool-subagent-control/list-agents` 子路径导出被移除
  （宿主 commit `4df09d37d5`，`packages/subagent/tool-subagent-control/package.json` 当前无该 export）；
  再写这一行会让**整个预设 broken**，所有 `agentPreset=omb` 的旧会话显示"会话不可用"。
- `tool-subagent` 的配置键 `modelSelectionSettings` → `modelSelection` + `modelDiscovery`；
  旧键被 schemastery 静默合并（`vendor/schemastery` 的 `strict=false`）、永不生效。
- **修法**（已在 `cordis.patch.yml` 生效）：删掉 list-agents 行、改键名。
  护栏：`tests/dsh/preset-composition.test.ts` 新增两条断言（子路径行不得出现、
  必须出现新键且不得出现旧键）。

## 3. 发布依赖 `workspace:*`：外部 profile 的插件操作全挂

### 3.1 症状（可复现）

任何把 `@omb/plugin` 作为 `file:`/git 依赖装进 DSH profile 的安装，在 pnpm 解析插件
dependencies 时失败：

```
[ERR_PNPM_WORKSPACE_PKG_NOT_FOUND] In : "@omb/artifact@workspace:*" is in the
dependencies but no package named "@omb/artifact" is present in the workspace
This error happened while installing the dependencies of @omb/plugin@4.22.0
```

DSH 插件管理器每次装/卸/切换都会重跑 `pnpm install`，所以**该 profile 的所有插件操作一起失败**。

最小复现（本机跑过，`pnpm 11.28.5`）：

1. 临时目录造 `repo/pkg-a`（`@t/a`）与 `repo/pkg-b`（`@t/b`，`dependencies: {"@t/a":"workspace:*"}`）；
2. 造 `consumer`（`pnpm-workspace.yaml` 只含 `.`），`dependencies: {"@t/b":"file:<repo>/pkg-b"}`；
3. `pnpm install` → 上面那条错误逐字出现。

### 3.2 根因

`workspace:` 协议**只在"当前 workspace 里存在该包"时可解析**（pnpm 的 workspace 协议）。
OMB 仓库里 7 个组件是 workspace 成员所以本机没问题；一旦插件被外部 profile 安装，
消费方 workspace 里没有 `@omb/*`，解析立即失败。

### 3.3 修法与为什么运行时不受影响

- 7 个 `@omb/*` 从 `dependencies` **移到 `devDependencies`（仍是 `workspace:*`）**。
  消费方安装依赖时不装 devDependencies，因此 pnpm 永远不会再看到这些 `workspace:`。
- 仓库内 `pnpm install` 仍会在 `node_modules/@omb/*` 生成指向 `packages/*` 的链接；
  **部署副本**（`node_modules/@omb/plugin` 的完整 clone）带着这些链接，
  Loader 从插件目录解析 `@omb/<组件>` 时命中的就是它们 —— 运行时解析不变。
- `scripts/build.mjs` 的依赖核对同步改为：devDependencies 必须挂 7 个组件、
  dependencies **不准**出现组件；任一违反都会在构建前失败。
- 新护栏 `tests/dsh/installable-manifest.test.ts`：所有随包发布的 manifest 的
  `dependencies`/`optionalDependencies` 不得出现 `workspace:`/`link:`；
  `files` 必须包含 `packages` 与 `cordis.patch.yml`。

### 3.4 已核对但未采用的方案

| 方案 | 结论 |
| --- | --- |
| 组件改 `file:packages/<dir>` | 消费方能装上，但 pnpm 会把组件**复制**进 `node_modules`；组件入口是从包内指向仓库 `lib-gen` 的转发桩，复制后相对路径会逃出包目录（部署布局另有转发规则）。放弃。 |
| 组件改 `link:` | 消费方安装副本里的链接指向副本外的路径，`require` 直接失败（实测）。放弃。 |
| 保留 `workspace:*` 只改部署脚本 | 外部用户从 git/tarball 安装时仍会失败，只修本机不算修。放弃。 |

## 6. 边界（如实记录）

1. **外部 profile 的 pnpm 操作只做了"最小复现 + 修法验证"，没有在别人的 profile 上实跑一遍**；
   需要对方（或用户）触发一次装/卸/切换确认 `ERR_PNPM_WORKSPACE_PKG_NOT_FOUND` 消失。
2. **UI 视觉未在浏览器里核对**：hover 颜色、子会话缩进、极窄宽度都只能从 token/样式与代码断言；
   `dsh web` 重启后请实际看一眼。
3. `engines.dsh = "=0.2.1-rc.3"` 是**精确钉版**：宿主一旦升到未核验构建，bundle 会被跳过
   （启动时会打印 `skipping profile bundle …`）。这是刻意的，不是遗漏。
4. 宿主 1533 个提交的改动面远大于本轮核到的四处；本轮只覆盖 **OMB 实际读取/渲染** 的接触面
   （会话头、主题 token、三个投影、委派行）。其余未接触面（jobs、web、desktop 等）未逐条审。
