# v4.23.0 — 设置台第二轮重做（x2）

> 本轮把设置台里"看起来像状态机"的地方改成**真正的会话时空状态机**，并按用户逐条反馈重做
> 导航高亮、下拉控件、检索栏、项目树展开与响应式。**没有新增模型工具、没有新增常驻提示**；
> 所有改动都在 `packages/memory/client.js`、`modules/memory/ui.ts`、`kernel/abi/session-situation.ts`
> 与 `modules/memory/index.ts` 的接线。契约与边界见 §9。

## 1. 状态机页：记忆控制器 → 会话时空状态机

**之前**：`GET /omb/api/machines` 聚合的是**记忆控制器**（v4.13 的 `phase/tasks/candidates`），
页面看起来"全是会话，没有状态机"。

**现在**：`ui.machines()` 改读 `SERVICES.sessionState.situation(sessionId)`（`dsh/state-machine.ts`
的 `SessionSituation`），按工作区分组，展示四类事实：

| 类别 | 字段 |
| --- | --- |
| 世界身份 | `epoch`: `head` / `branch` / `dirtyCount` / `at` / `degraded` / `source` / `instructions`（是否有指令指纹） |
| 我信过什么 | `reads`: `count` / `changed` / `unknown` + 按路径的 `entries[]`（`same` / `changed` / `unknown`） |
| 增量与守卫 | `sideEffects`: `blindWrites` / `staleWrites` / `denies` / `gaveUps` / `unverifiable` / `shellWrites` / `shellUnknown` / `shellInferred` / `otherSessionWrites`；`workspace.switches` / `previousRoot` |
| 时间与意图 | `state`（active/idle/stale/recovering）、`tier`、`turn` / `step`、`lastEventAt` / `idleMs`、`lastTurnEndReason`、`interrupted` / `unresolved`、`goals` / `todos` |

**诚实降级**：`observed === false`（本进程没见过该会话：历史会话、重启前会话、未被事件推进）
显示"未观测"与原因，**不把没读到画成 0**。归档/封存会话不读状态（显示"归档/封存：不读状态机"）。

**留了一条明确的边界**：记忆控制器的任务/候选编辑**仍在项目页的「会话设置」里**
（`ControllerSection` → `GET/POST /omb/api/controller`），只是不再冒充"状态机总页"。

类型：新增 `kernel/abi/session-situation.ts`（模块只依赖结构最小面，不 import 宿主）；
`modules/memory/index.ts` 的 `createUiService` 注入 `situationOf`。

## 2. 二级导航：选中高亮改成滑动块

**之前**：`.omb-nav-cell[aria-current='page']` 原地换底色（淡入淡出）。

**现在**：nav 里只有一个 `.omb-nav-indicator` 绝对定位块；`MemoryPanel` 用
`offsetTop/offsetHeight` 测量当前项，`transform: translateY(...)` + `height` 过渡：

```
transition: transform 340ms cubic-bezier(.38, .02, .2, 1.4),
            height 340ms cubic-bezier(.38, .02, .2, 1.4),
            opacity 220ms;
```

- **首次选中只淡入**：`data-animate='false'` 时只过渡 opacity，位置/高度在
  `useLayoutEffect` 里**无过渡就位**；下一帧 `requestAnimationFrame` 才把
  `data-animate` 打开（否则会从 `top=0,height=0` 滑下来，看起来像回弹）；
- **随后切换都是滑动回弹**：起步慢（起始斜率约 .05）、中后段加速、末尾
  `y2=1.4` 的过冲再收束（第四轮："整体变慢了没那么 q 弹，快一点"→ 340ms、加大过冲）；
  过渡为**内联样式**：CSS 后置规则——尤其是
  `@media (prefers-reduced-motion)` 的 `transition: none`——曾把回弹覆盖掉；
  减弱动效改由 JS 的 `matchMedia` 显式判断；
- `ResizeObserver` 监听 nav 宽度变化（56px ↔ 190px）重新测量；
- 菜单项间距 2px→**4px**；
- **侧栏尺寸只有一个切换点**：容器 <980px 恒为 56px 图标轨，≥980px 才是 190px
  带文字；此前 617 与 760 两处各调一次宽度（56→52→190），拖动窗口时会连续跳，
  看起来像"大小抖动"（本轮已清掉）。

## 3. 菜单型下拉框（仿 dsh-desktop-notify）

原生 `<select>` 整体替换为自定义 `Select`（`function Select`）：

- **触发器**：32px、无边框、`--dsw-alias-bg-module-platform`、8px 圆角、左对齐文字、右侧 chevron；
- **浮层**：大圆角（`--dsw-radius-lg`）、**玻璃透明**（`color-mix(... 74%, transparent)` +
  `backdrop-filter: blur(20px) saturate(1.4)`）、**无边框**、`drop-shadow` 阴影、
  `omb-menu-in 130ms` 入场；
- **按侧对齐**：打开时测量触发器中心，位于视口左半 → `data-align='left'`（`left: 0`），
  右半 → `data-align='right'`（`right: 0`）；
- 点外部 / Escape 关闭（`useMenuDismiss`，与 desktop-notify 同款）；
- 选中项打勾（`IconCheckOutlineRegular`），键盘可操作（原生 button + `role=option`）。

> 为什么不用原生：原生下拉浮层外观跟系统走，做不出上面这套；desktop-notify 的注释也这么写。

## 8. 响应式与动画

- 详情并排断点 **820 → 560px**：820 落在常见窗口宽度里（宿主侧栏展开/收起会改变面板宽度），
  拖动窗口时会在"覆盖/并排"之间反复横跳；560 在常规宽度下不会被跨到；
- 并排时 `.omb-list-pane { flex: 1 1 0 }`，详情 `flex-basis: clamp(280px, 46%, 560px)`
  用 220ms 过渡；
- 覆盖模式：`.omb-list-pane` 从 `opacity:0; pointer-events:none` 改为
  **`opacity:0; transform: translateX(-10px)` + 180ms 过渡**（不再瞬间消失），
  详情仍在 220ms 内滑入；
- 统计卡：带状态点的卡不再用 `.omb-meta`（12/18），值统一 `.omb-card-value`（17/26 + flex），
  同排卡片高度一致；`.omb-grid + .omb-note` 补 8px 上间距。

### 8.1 712px 抖动的根因：容器查询 content box 自我反馈（已修）

`container-type: inline-size` 的查询尺寸是**容器的 content box**。旧代码在
`@container (min-width: 618px)` 里改 `.omb-page` 自己的 `padding`：

1. 面板 656px → content box 616px（<618）→ 小 padding；
2. 小 padding 使 content box 变成 624px（≥618）→ 切到大 padding；
3. 大 padding 又把它压回 616px → 再切回小 padding……

阈值附近（约 **618 ± 面板 padding**，在宿主收起一级侧栏时正好落在窗口 **712px 附近**）
两个状态互相触发，形成**翻转死循环**；再叠加 padding 的 180ms 过渡，页面里大量元素
（卡片、工具栏、导航）一起"抖"。这也解释了"包括很多东西"。

修复：容器查询里**不再修改容器自身的 `padding/gap`**（只改内部 `.omb-content` 的
内边距、网格列数、导航宽度），并移除 `.omb-page`/`.omb-content`/`.omb-nav` 上
跟随布局变化的过渡（布局切换即时完成；动画只保留给交互：导航滑块、展开、详情、子页切换）。

### 9.1 第二轮反馈（v4.23.0 内追加）

1. `.omb-list` 行间距 → **8px**；
2. 记忆/项目/状态机的操作与画像一致：表单/取代弹窗的失败也弹 Toast（成功已有）；
3. 收起态 `.omb-collapse` 高度 0 + flex gap 造成空白翻倍 → 负 margin 抵消；
4. 「个人画像」→「画像」；
5. 所有子页加载统一一行「正在加载中...」；
6. 下拉项间距 2px、`flex: none`，选中高亮与相邻 hover 不再上下边重叠；
7. 下拉左右对齐改用**面板中心**（`.omb-page` 矩形），不再用窗口中心（要扣掉 DSH 一级侧边栏）；
8. 手动新建：内容哈希扫描最近 500 条 + **串行队列**，并发双击只留一条；
9. 状态机页只列**本进程观测到 situation 的会话**（无读数的历史会话不再冒充状态机）；
10. **`@omb/memory: import failed` 的两个真因**：① clone 的 `packages/*/lib-gen/g<N>` 转发桩
    gitignored，`git reset` 后丢失（部署要复制两份）；② CSS 模板字符串的注释里写了反引号，
    提前关闭模板，剩余 CSS 被当 JS 求值 → `ReferenceError: page is not defined`，
    整个 bundle import 失败。②已加护栏测试：CSS 模板内不得出现反引号。

**未验证 / 如实记录**：

1. 没有浏览器控制权：滑动高亮的手感、玻璃浮层的实际观感、断点切换的平滑度需要重启
   `dsh web` 后实际点一遍；
2. 状态机页只展示**本进程观测到**的会话；历史会话写"未观测"是刻意的，不是缺数据；
3. 记忆控制器的手动编辑仍在项目页「会话设置」，本轮没有删掉该能力；
4. 搜索/筛选仍是前端内存过滤（有 500 条扫描上限），不是服务端全文检索。
