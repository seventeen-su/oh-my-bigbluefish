# OMB v4.10.0 — 检索过滤与模糊回退

> 用户指令第 2 项（x2 新功能）：`omb_recall` 增加**模糊搜索**与**类型 / 状态 / 标签过滤**。
> 类型过滤（`kinds`）此前已有；本版补齐状态、标签与子串回退，并把标签写进记忆 schema。

## 1. 标签（schema v6）

- `memory.tags`：JSON 字符串数组，`ALTER TABLE ... DEFAULT '[]'`（纯加法，旧库原地升级）；
- `MemoryRecord.tags?: readonly string[]`；读库时归一为 `[]`；
- 写入校验：数组、去空白后非空、每个 ≤24 字符、最多 8 个、去重保序；
  违规**直接拒绝**（标签是检索条件，静默截断会让"按标签查"不可解释）；
- `omb_remember` 新增可选参数 `tags`（同校验）；召回头部显示 `标签 a,b`；
- `kernel/abi/storage.ts` 的 `SCHEMA_VERSION` 抬到 **6**，迁移步骤 `memory-tags`。

## 2. 检索过滤

`omb_recall` 参数（全部可选）：

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `kinds` | episodic / semantic / procedural | 类型（已有） |
| `status` | active（默认）/ stale / superseded / all | 状态：默认只看有效条目 |
| `tags` | 字符串数组 ≤8 | 标签过滤，多个标签是 **AND** |
| `fuzzy` | true（默认）/ false | 词法 0 命中时是否做子串回退 |

下推位置：SQL（`statusClause` / `tagsFilterClause`，`json_each` 做 AND 匹配），
不是 JS 事后裁剪；向量通道同样遵守同一组过滤。显式查 `stale/superseded/all` 时，
检索后的兜底过滤与"过时探测"会跳过（否则会把调用方要查的行再丢掉）。

## 3. 模糊回退

- 触发条件：某库**词法通道 0 命中（或全部低于下限）**且 `fuzzy !== false`；
- 实现：`MemoryStore.searchFuzzy?`（可选端口）用 `LIKE ... ESCAPE` 做**有界**子串匹配，
  查询串截到 120 字符、`LIMIT` 有界、遵守状态/类型/标签过滤；
- 结果通道标记 `fuzzy`，分数只用于通道内排序；召回头部显示"信号 模糊子串"；
- 老实现没有 `searchFuzzy` 时静默跳过（不假装支持）；`fuzzy=false` 即严格词法（回归对照）。

## 4. 边界

- 模糊回退是**词法兜底**，不是语义检索；跨语言/语义相似仍靠向量通道（可关）；
- `LIKE` 不走 FTS 索引，只在 0 命中时触发，代价有界；
- 标签过滤是 AND；需要"任一标签"时由调用方分多次查询（避免把 OR/AND 混在一个参数里）；
- 状态过滤放开的是"读取面"，不改变写入/晋升规则；失效条目仍会逐条标注。
