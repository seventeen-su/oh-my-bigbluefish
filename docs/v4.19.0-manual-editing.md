# OMB v4.19.0 — 设置台手动编辑扩展（交付记录）

> 用户补充：“状态机等也应当应用手动编辑等”，并确认三类都要：
> ① 记忆控制器的会话状态（任务约束/候选）；② 个人画像条目；③ 记忆生命周期（含指定取代目标）。

版本 **4.19.0（x2）**，构建 **g136**；契约见本文，界面规范沿用 `DESIGN.md` 与
`docs/v4.18.0-ui-contract.md`。

## 1. 控制器状态机（项目页）

ABI 新增 `SERVICES.memoryControllerAdmin = 'omb:memory-controller-admin'`
（`kernel/abi/controller-admin.ts`）：
`{ state(sessionId): ControllerAdminState; edit(sessionId, edit): ControllerAdminState }`。
ABI 不 import 模块，状态/编辑形状是结构化最小接口。

模块侧（`modules/memory/capture.ts`）：

- `Capture.controllerState(sessionId)`：只读；不创建缺失会话，返回空状态。
- `Capture.editController(sessionId, edit)`：五个动作
  `add-task` / `remove-task` / `clear-tasks` / `remove-candidate` / `clear-candidates`。
  - 任务：文本 1..200、去重、上限 `MAX_CONTROLLER_TASKS`、TTL `CONTROLLER_TASK_TTL_MS`；
  - 候选：按文本移除或清空（候选来自控制器，不由 UI 新建）；
  - 改表后 `phase = derivePhase(...)`、`transition = null`（手动编辑不是事件转移）；
  - 未知会话/非法动作返回原状态；全程 try/catch，绝不抛。

UI 服务 / 路由：

- `ui.controller(sessionId?)` → `UiControllerView`：`available/reason/sessionId/phase/tasks/candidates/lastEventAt`；
  缺省取当前会话；未接线、无会话、异常都返回**完整降级形状**。
- `ui.controllerAct(input)`：sessionId 必填（trim ≤200）、动作白名单、文本校验。
- `GET /omb/api/controller?sessionId=`；`POST /omb/api/controller`
  （JSON、同源、4KB、200/400/409；405 文案含 `/controller`）。**没有模型工具入口**。

界面（项目页 → 选中会话 → “状态机”）：

- 阶段标签（空闲/待确认候选/跟踪任务/混合）、任务数/候选数；
- 添加任务输入 + 按钮；每条任务/候选卡片带“移除”；
- “清空任务/清空候选”走确认 Modal；
- 提示“手改立即生效，任务在回合结束失效”。

边界：控制器状态是**进程内会话状态**，宿主重启后为空；归档会话不展示编辑
（项目页归档态只显示“不可读”）。

## 2. 个人画像（个人画像页）

`ProfileService.retract({axis,key}, sessionId?)`（v4.19）：

- 只删 `declared` 条目；inferred 不走 retract（提示用 `clearDeduced`）；
- **删除单位是槽位**：同轴同键的显式声明一起删（矛盾声明同时消失）；
- 找不到 → `ok:false` + 可读原因且不写入；写后 `load` 查回，仍在 → `ok:false`；
- capability 轴拒绝；空 key/未知轴拒绝；绝不抛；
- `writeFaceCalls`/文案如实计入 retract。

UI 服务 / 路由：

- `ui.personalAct(input)`：`declare`（axis/key/value/evidence，value ≤2000，axis 排除 capability）
  或 `retract`（axis/key）；经 `SERVICES.profile` 的 `declare`/`retract`；
- `POST /omb/api/personal`（JSON/同源，200/409/400）；GET 不变。

界面（个人画像页）：

- “新增条目”Modal：轴（稳定偏好/意图/协作方式）× 键 × 取值 × 依据；
- 每条条目：`编辑`（已声明 → 先 retract 同键旧声明再 declare；推断 → declare 覆盖同键推断）；
- 已声明条目可 `删除`（Modal 确认）；推断条目给 `改为确认`；
- 保存/删除后重读 `/personal` 并提示结果；冲突区仍只呈现不裁决。

## 3. 记忆生命周期：指定取代目标（记忆页）

详情动作新增 `取代…`：打开 Modal，搜索并选中另一条活跃记忆，`POST /omb/api/resolve`
`{action:'supersede', fromId, toId}`（既有非破坏语义：旧条目写 validTo/supersededBy + 边，
历史保留）。确认、过时、恢复继续在详情动作条；相关记忆卡仍可直接“本条取代该条”。
