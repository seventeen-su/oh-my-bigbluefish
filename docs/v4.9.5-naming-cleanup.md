# OMB v4.9.5 — 命令简介精简与过程卡隐藏

> 两处用户可见噪音的收尾（x3）：四个记忆命令的简介太长、带括号；8 张过程卡被
> DSH 当成用户斜杠菜单的一部分，出现 `/omb-r1`…`/omb-r8`。

## 1. 四个用户命令的简介

只改注册的 `description`（用户命令菜单里显示的那一行），不改命令名与用法文本：

| 命令 | 旧简介 | 新简介 |
| --- | --- | --- |
| `/omb-privacy` | 设置当前对话记忆库隐私开关 | 设置当前对话的记忆隐私模式 |
| `/omb-privacy-clean` | 清除当前/指定会话或全部已结束会话的受限记录 | 清理对话的隐私限制记录 |
| `/omb-feedback` | 对记忆条目给一次显式反馈（useful / wrong / stale / noise；不新增模型工具） | 标记记忆是否有用、过时或不对 |
| `/omb-confirm` | 确认候选记忆（可撤销；用户显式动作，只改证据归属，不改正文与来源） | 确认候选记忆，可撤销 |

原则：一行说清"这条命令对你做什么"，不放参数枚举与设计解释；参数含义留在 `input.hint`
与 `help` 输出里。

## 2. 过程卡不再当用户指令

8 张过程卡是**模型技能**（按需加载的推理规则），不是用户命令。DSH 的 skills
默认 `userInvocable: true`，会被列进 `/` 菜单并渲染成 `/omb-r1` 一类噪音。

修复：每张卡的 frontmatter 增加

```yaml
user-invocable: false
```

（DSH `skill-filesystem` 的官方键；`modelInvocable` 仍为 true，模型仍能在技能目录里发现并加载。）

同时把编号名换成有语义的名字（模型侧目录更可读，见 `docs/v4.9.5-naming-cleanup.md` 末表）：

| 旧 id | 新 id |
| --- | --- |
| omb-r1 | omb-depth |
| omb-r2 | omb-goal |
| omb-r3 | omb-options |
| omb-r4 | omb-testable |
| omb-r5 | omb-cite |
| omb-r6 | omb-failure |
| omb-r7 | omb-honesty |
| omb-r8 | omb-conflict |

描述同步压缩为一行（≤120 字符、无括号、不再写"何时用："套话）；正文保留原意，
`tests/modules/reasoning/skills.test.ts` 钉住：
`user-invocable: false`、目录名 = `name`、描述短且无括号、正文锚点句仍在。

常驻提示同步：`过程卡见 skills：omb-depth 等。`

## 3. 明确边界

- 隐藏只影响**用户可见的斜杠菜单**；模型仍通过技能目录发现这些卡（`modelInvocable` 不变）；
- 报告里出现了 `user-invocable: false` 只是声明，**真机验收仍需重启 `dsh web`** 后确认
  菜单里不再出现 `/omb-r*`；
- 旧 id 不再存在：依赖 `skill omb-r1` 的旧习惯会失效（这是本次有意收口）。
