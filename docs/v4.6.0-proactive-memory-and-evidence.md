> **4.6.1 修正**：本文关于证据“成功/失败”和“修复已验证”的描述已被
> `docs/v4.6.1-review-fixes.md` 收紧——成功改为解析 `[exit code: N]` 而不是工具 isError，
> `verifiedFix` 改名 `recoveredFromFailure`（仅表示失败后再次成功）。

## 1. 主动记忆（用户新增需求）

### 1.1 常驻提示：同时点"写"

旧提示只有 `跨会话结论用 omb_recall 查`——只教模型"查"，没教"写"。
现在：

```text
长期偏好/决定主动 omb_remember；跨会话结论先 omb_recall
```

- 仍逐字节稳定，进静态前缀；长度 ≤40，与推理短变体合计 ≤120（有测试）；
- 只点"何时用"，不扩容成散文。

### 1.2 工具描述：触发条件前置

- `omb_remember`：开头改为"用户表达长期偏好/决定、纠正旧结论、或你得到可复用结论时
  **主动调用**，不要等用户提醒"；并提示纠正旧结论要先 `omb_recall` 拿旧 id，
  再用 `supersedes`。
- `omb_recall`：增加"写新结论前先查重；纠正旧结论时先召回旧条目"。

### 1.3 易变提示：只在用户消息命中明确信号时出现

新增 `modules/memory/proactive.ts`（确定性纯函数，热路径零 LLM）：

| 信号 | 判据 | 提示 |
| --- | --- | --- |
| 显式要求记住 | 记住/帮我记/别忘了/记下来… | 立即 `omb_remember`，不要只回"好的" |
| 纠正旧结论 | 不对/错了/改主意/改成/更正/撤销/之前说… | 先 `omb_recall`，再 `omb_remember(supersedes)` |
| 项目决定 | 决定/采用/统一用/约定/以后都… | 记 `semantic` 项目库并写来源 |
| 长期偏好 | 喜欢/习惯/偏好/总是/一直… | 记 `semantic` 用户库 |

- 只对**用户消息**生效，普通问句/闲聊/超长粘贴不提示（测试钉住）；
- 走 `prompt:omb-memory` 的**易变 `context` 槽**，不进口述常驻；
- 每会话一条，下一条无信号消息覆盖，`turn/end` 清空（有测试）；
- 提示是一行 ≤120 字符的事实句，含具体工具名与下一步动作。

## 2. 项目运行证据闭环（审查第 5 点）

### 2.1 新服务：`SERVICES.projectEvidence`

`dsh/project-evidence.ts` 记录 `dsh/` **亲眼看到**的工具结果：

- 只认 `tool/result/observed` 里带 `tool + args + ok` 的结果；
- 只认 shell 类工具，从参数抽 `command`；抽不到/无法归类/无法归属项目 → `skipped`；
- 类别：`test / build / typecheck / lint / verify / install`；
- 项目根经 `SERVICES.activeSession` + `SERVICES.projectRoot` 解析，子目录会话归到同一根；
- 有界：每项目最近 8 条、最多 16 个项目；
- **落盘**：`<projectRoot>/.omb/evidence.json`（可关），进程重启后仍能回答
  "上次失败的是哪条命令、修复后有没有再跑过"；
- **修复已验证**：同一命令此前失败、这次成功 → 该条标 `verifiedFix`（只是证据标记，
  不自动升级任何记忆层级）；
- **脱敏**：命令里的 `token=…` / `password: …` / `Bearer …` 先替换为 `***` 再记录/落盘。

### 2.2 `omb_project` L1：结构 + 运行证据并排

L1 结构行末尾追加：

```text
证据：测试✅ pnpm test 10 分钟前；构建❌ node scripts/build.mjs 2 小时前
```

失败后同一命令再次成功时显示 `（修复已验证）`。三种说法严格分开：

- 服务未接线 → `证据未接线（…不是"没有运行证据"）`；
- 已接线但本进程/本工作区无读数 → `本进程暂无构建/测试读数（不是"没跑过"）`；
- 有读数 → 成功/失败 + 命令 + 相对时间。

这样地图不再只是"导入边/调用边"，而是与**真实构建/测试结果**同一个入口可见。
仍未做：故障复现脚本与"已验证修复"的自动关联（当前只按同一命令失败→成功标记）、
证据与具体节点（文件/符号）的精确映射；当前先做"项目级证据"。

## 3. 统一知识生命周期（审查第 6 点）

新增 `modules/memory/lifecycle.ts`：阶段由 `kind + assertedBy` **推导**，不加列、不靠召回次数：

| 记录形态 | 阶段 |
| --- | --- |
| `episodic` | 事件 |
| `semantic` + `user` | 已确认 |
| `semantic` + 其他 | 候选 |
| `procedural` + `user` | 经验 |
| `procedural` + 其他 | 候选 |

- 召回回执每条显示 `阶段 事件/候选/已确认/经验`；`omb_project` L4 每行显示 `kind/阶段`；
- **没有自动晋升路径**：`useCount`/召回次数不参与推导，想升级只能由用户显式确认；
- v4.5.3 的 `decideLifecycle` 继续拦"执行确认 → procedural"。

仍未做：用户显式晋升命令与晋升审计（当前阶段是只读推导，不能人工提级）。
